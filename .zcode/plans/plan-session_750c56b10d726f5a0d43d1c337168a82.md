# Thermite — Implementation Plan

Rust thermal management suite for the Acer Nitro V 15 (ANV15-51, BIOS V1.60, i5-13420H + RTX 4050, Arch, kernel 7.2): privileged daemon + CLI + GPUI GUI providing fan control, custom fan curves, thermal monitoring, and performance profiles.

## 1. Evidence Base (from the investigation)

**Hardware control path is settled — mainline WMI, not EC RAM.**
- Local probe: this machine currently exposes **zero** fan/pwm/platform_profile interfaces (acer_wmi inert, ec_sys unloaded, no fan hwmon, NVIDIA driver has no hwmon — NVML only). Telemetry sources available today: coretemp, 2×nvme, acpitz, SEN2–5 thermal zones, iwlwifi, NVML.
- EC RAM writes are a **proven dead end on ANV15-51** (nbfc-linux #219: duty writes 0xF5/0x54 ignored; fan control moved to chipset-MMIO mailboxes reachable only via WMI). AN515-era EC register maps do not apply. **Thermite will never write EC RAM.**
- Mainline `acer-wmi` gained WMI fan control (hwmon temps/RPM + `pwmX_enable` + platform_profile) in Oct 2025. An ANV15-51 quirk (`cpu_fans=1, gpu_fans=1, hwmon, platform_profile, pwm`) was **accepted upstream 2026-10-05** — tested on exactly BIOS V1.60, both fans independently controllable, `pwm_enable=2` restores auto, turbo profile rejected with EIO. It ships in kernel 7.3, not 7.2.
- On kernel 7.2, `modprobe acer_wmi predator_v4=1` enables monitoring + profiles but **not pwm** (verified in mainline source: param sets only `quirk->predator_v4`, no `ACER_CAP_PWM`).
- Reference project (Div-Acer-Manager-Max: Avalonia GUI + Python daemon + 143KB forked kernel module) weaknesses we fix: no standard hwmon (invisible to CoolerControl), no fan curves (single fixed %), no failsafe/watchdog/suspend handling (resume-storm bug #253, 10s firmware reverts #136), kernel-7.2 build breakage, replaces/blacklists acer_wmi.

**Kernel-driver decision (explicitly closed):** no new/ported EC driver — mainline already provides the interface; a custom driver offers no reliability/safety/maintainability advantage. The only kernel artifact is a **temporary DKMS stopgap** carrying the already-upstream-accepted ANV15-51 quirk (patched copy of `acer-wmi.c` + Makefile) so full control works on 7.2 today; auto-deprecated when 7.3 arrives.

## 2. Architecture

Cargo workspace, edition 2024, clippy/rustfmt clean, git repo from day one:

```
thermite/
├── crates/
│   ├── thermite-core     # pure logic: curve engine, hysteresis, profiles, config, sensor model, Backend trait — no I/O
│   ├── thermite-backend  # sysfs + NVML (+ optional ec_sys read-only) backends, capability detection
│   ├── thermite-proto    # IPC types (serde), versioned protocol
│   ├── thermite-daemon   # root systemd service: control loop, failsafes, UDS server
│   ├── thermite-cli      # `thermite` binary (clap)
│   └── thermite-gui      # `thermite-gui` GPUI binary (unprivileged)
├── driver/acer-wmi-anv15/  # optional stopgap DKMS module (temporary)
├── packaging/              # systemd unit, sysusers/tmpfiles, polkit action, AUR PKGBUILDs
└── docs/                   # INVESTIGATION.md (findings + sources), SAFETY.md, ARCHITECTURE.md, HARDWARE.md
```

**IPC:** Unix domain socket `/run/thermite/thermite.sock` (0660, root:`thermite` group), length-prefixed JSON, `SO_PEERCRED` auth, versioned handshake, request/response + server-push events (1Hz telemetry, state changes, alerts). Chosen over D-Bus: no desktop-integration need for a single-user tool; one protocol for CLI and GUI; trivially testable. GUI falls back to unprivileged read-only sysfs mode when the daemon is absent.

## 3. Hardware Backend (`thermite-backend`)

Capability-probing trait (`Backend`) with three implementations:
1. **AcerWmi (primary)**: `/sys/devices/platform/acer-wmi/hwmon*/` fan RPMs, temps, `pwmX_enable` (0=turbo, 1=custom, 2=auto — inverted vs hwmon convention), pwm duty; `/sys/firmware/acpi/platform_profile`. Detects capability level: FULL (quirk present / 7.3 / stopgap), MONITOR+PROFILES (`predator_v4=1`), or NONE — degrades gracefully.
2. **SysfsSensors**: hwmon scan (coretemp, nvme, acpitz, iwlwifi, SEN zones), power supply status.
3. **Nvml**: GPU temp/power via `nvml-wrapper` (driver 615 exposes no hwmon); optional compile.
Optional `ec_sys` read-only sensor source (EC MMIO 0x58/0x59/0x5C/0x6A via `/sys/kernel/debug/ec/ec0/io`), off by default — supplementary only, never writes.

## 4. Daemon — control loop & safety (the centerpiece)

`thermite.service`: `Type=notify`, `WatchdogSec=30` (sd_notify), OOM hardening (`OOMScoreAdjust=-1000`), restart with backoff. 1s control tick:
- **Curve evaluation** → duty per fan; writes rate-limited; re-assert mode+duty every 2s and on drift (RPM vs commanded) to defeat firmware overrides (DAMX #136).
- **Thermal failsafe**: T_warn (default 87°C CPU / 82°C GPU) → force full duty; T_crit (92/87) → `pwm_enable=2` (firmware auto) + alert + never re-enter manual until temps recover. Curve validation at load: monotonic temps, duty 0–100, min-duty floor enforced (≥30% above 60°C, no 0-RPM above 45°C).
- **Suspend/resume**: subscribe logind `PrepareForSleep` (zbus, blocking client, this single use); on sleep → restore auto; on resume → wait 20s (EC reinit takes 12–15s, DAMX #253), debounce power-source (3 consecutive samples), re-apply.
- **Crash safety**: `ExecStop`/`ExecStopPost` → `pwm_enable=2`; periodic re-assert means a dead daemon loses control gracefully (firmware auto resumes). Single-writer guard (socket bind + pidfile) + warn when pwm state changes not authored by us (CoolerControl coexistence).
- **Modes**: auto | manual(%) | curve(name), per fan; battery vs AC strategy selection.
- **`--dry-run`**: full loop, logs intended writes, touches nothing (also used by tests).

## 5. Config & Curve Engine (`thermite-core`)

TOML at `/etc/thermite/thermite.toml`: general (poll interval, failsafe thresholds), profiles, fan curves, power-source bindings. Curves: piecewise-linear `[temp_c, duty_pct]` points per fan per profile per power source, linear interpolation, hysteresis (downshift requires Δ−2°C held 5 ticks), min/max clamps. Well-tested pure functions: property tests (interpolation bounds, hysteresis state machine, validation rejects bad curves).

## 6. CLI (`thermite-cli`, clap)

`status` · `monitor` (live table) · `profile get/set` · `fan auto|set N|curve <name>` · `curve list/show/validate` · `config check/edit` · `daemon status` · `doctor` (capability report: kernel, quirk presence, predator_v4, pwm files, permissions, NVML, sensors found — doubles as on-target verification) · `version`. Table output, `--json` everywhere.

## 7. GUI (`thermite-gui`)

`gpui 0.2.2` (crates.io) + `gpui-kit 0.7` (Apache-2.0, production-proven at Longbridge; provides charts/tables/widgets — directly covers live sensor charts). Dark-first theming with accent color, clean typography — a deliberate upgrade over DAMX's dated look, but strictly M5 polish (engineering first). Single window, left nav:
- **Dashboard**: rolling temp/RPM/duty charts, sensor table, alerts.
- **Fans**: per-fan card — mode switch, duty slider (manual), live RPM.
- **Curves**: 2D editor, draggable points on temp×duty canvas (custom GPUI element via paint primitives), live operating-point overlay, per-profile/power-source tabs.
- **Profiles**: cards (quiet/balanced/performance + low-power; turbo hidden — firmware EIO).
Unprivileged, talks to daemon; absent-daemon banner + read-only mode. UI crate kept thin behind IPC types so toolkit risk stays contained.

## 8. Packaging

`packaging/`: systemd unit + sysusers (`thermite` group) + tmpfiles; AUR-ready PKGBUILDs (`thermite`, `thermite-acer-wmi-anv15-dkms` stopgap with conflict/deprecation notes). docs/: full investigation findings with sources, SAFETY.md (failsafe design + what we never do: EC writes), HARDWARE.md (ANV15-51 WMI/EC knowledge), ARCHITECTURE.md.

## 9. Testing

Unit (curve/hysteresis/validation), integration with `FakeBackend` (in-memory + tempdir sysfs fixtures), daemon-over-real-UDS integration tests, `--dry-run` daemon mode, `thermite doctor` as the on-target smoke test. No hardware required for CI; hardware steps run manually via doctor.

## 10. Milestones

- **M0 — Hardware verification** (first implementation step, needs your sudo, ~30min): `modprobe acer_wmi predator_v4=1` → confirm hwmon/profiles appear; build+load stopgap patched module → confirm `pwm1/2_enable` + independent fan control; record firmware-override timing and turbo-EIO. Restores prior state after. This validates every hardware assumption before code depends on it.
- **M1** — git init, workspace scaffold, thermite-core (curves, config, profiles) + tests.
- **M2** — backends + capability detection + `doctor` + telemetry-only daemon & IPC.
- **M3** — control loop, all failsafes, suspend/resume, systemd unit; complete CLI.
- **M4** — GUI dashboard, fans, profiles.
- **M5** — curve editor + theming polish.
- **M6** — stopgap DKMS package, AUR PKGBUILDs, full docs.

## 11. Risks & mitigations

Firmware reverts manual duty → 2s re-assert + drift detection (proven issue on sibling model). Resume EC reinit delay → 20s grace + debouncing (proven issue). Turbo profile EIO → hidden/disabled. GPUI churn → pinned crate versions, thin GUI crate. Stopgap DKMS vs kernel updates → DKMS rebuilds; capability layer never assumes it. NVML absent → fallback to WMI hwmon temps / acpitz. Out of scope (documented): EC RAM writes, GPU TGP unlock (firmware-stubbed NVPCF), keyboard RGB, battery charge limit (WMI-exposed by linuwu but not mainline — future contribution candidate), turbo profile.
