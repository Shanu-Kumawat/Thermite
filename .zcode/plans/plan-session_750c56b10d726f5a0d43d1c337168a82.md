# Thermite Generalization (pre-GitHub phase)

Goal: turn Thermite from a 2-fan Acer app into an N-fan, vendor-neutral driver architecture with no behavior regressions, plus close the known UI gaps — **before** the GitHub-ready pass. Config takes a clean break (only your machine runs it). No vendor driver code yet (Acer/HP/ASUS friends arrive in the GitHub phase); we design the seam so any of them is easy to add.

## 1. Core model: string fan IDs + fan descriptors (thermite-core)

- Replace the closed `FanId` enum (`sensors.rs:10-41`) with `FanId(Arc<str>)` (cheap to clone, serde-friendly) plus a `FanDescriptor { id: FanId, label: String, temp_source: TempSource }` reported by backends.
- Add `fn fans(&self) -> &[FanDescriptor]` to the `Backend` trait (`sensors.rs:246`); `set_fan_hw_mode`/`set_fan_duty` take the string id. Backends that don't know a fan return a clear error.
- `TempSource` enum (`CpuClass | GpuClass | Named(String)`) replaces the hardcoded `match fan_id { Cpu => cpu_t, Gpu => gpu_t }` coupling (control.rs:377-380). Acer reports `CpuClass`/`GpuClass`; keep a generic `Telemetry::temp_by_class()` aggregator (generalizes `cpu_temp_c`/`gpu_temp_c`).
- Move the Acer-inverted pwm_enable convention out of core: `HwFanMode` stays as an abstract intent, each backend maps it to its own hardware semantics; documented on the trait. This keeps non-sysfs drivers (e.g. EC-based HP paths) representable — the trait assumes nothing about how a driver talks to hardware.

## 2. Config schema v2 (thermite-core/config.rs) — clean break

- `FansConfig { cpu, gpu }` struct fields → `fans: BTreeMap<String, FanConfig>` (`[fans."cpu"]` TOML). Curves map is already fan-agnostic — unchanged.
- `Config::validate()` iterates the map (removes the 2-element literal at config.rs:261); validation errors when config names a fan the backend didn't report (with an available-fans hint), rather than silently ignoring.
- `PlatformProfile` closed enum → parse/serialize as strings validated against `CapabilityReport.platform_profiles` at runtime (config accepts any profile name the driver reports). Keep the known Acer names as documentation.
- Update `examples/thermite.toml` + your `/etc/thermite/thermite.toml` (I'll produce the exact new file; you install it with sudo).

## 3. Driver registry (thermite-backend) — vendor-neutral

- New `drivers/` module: `drivers/acer_wmi.rs` (moved + adapted from `acer_wmi.rs`) behind a vendor-neutral `Driver` trait — `fn name()`, `fn probe(sysfs_root) -> Option<Self>`. A driver is anything that can enumerate fans/temps and (optionally) control them; no assumption of sysfs pwm files or any particular kernel interface.
- `ThermiteBackend::probe()` (lib.rs:38) becomes: iterate registered drivers, first successful probe wins, attach NVML/system sensors as generic supplements regardless of driver.
- `CapabilityReport`: replace `acer_wmi_hwmon: Option<String>` with `driver: Option<String>` (+ per-driver detail string); `CapabilityLevel` reworded to driver-agnostic semantics.
- Fix the actively-wrong fallback at state.rs:183-187 (`"cpu" else Gpu`) — ids flow through as strings everywhere now.
- FakeBackend generalized: constructible with N fans (`FakeBackend::new(fan_names)` with a 2-fan convenience for tests), `set_temps` → per-class/per-name setters.

## 4. Daemon & proto

- proto: `Request::SetFanConfig { fan: FanId }` and `FanRuntimeState.id` become string ids; bump `PROTOCOL_VERSION` to 2. GUI and CLI updated in lockstep (no external clients).
- control.rs / dryrun.rs / state.rs: replace all `FanId::all()` iterations (control.rs:368, 612; dryrun.rs:45) with the backend-reported fan list held in SharedState; `PersistedState`/`effective_fans` (state.rs:75-83) seed from reported fans instead of hardcoded "cpu"/"gpu".
- All 60 existing tests updated (mostly mechanical `FanId::Cpu` → `FanId::from("cpu")`); add new tests: 3-fan control loop, config naming an unknown fan rejected, per-fan temp source selection.

## 5. GUI (thermite-gui)

- `Sample` ring (fixed `cpu/gpu/cpu_rpm/gpu_rpm` fields) → per-fan generic history: `BTreeMap<String, FanSample { temp, rpm }>` fed by fan descriptors; dashboard charts render per temperature class present + per fan (layout already iteration-shaped at main.rs:1925).
- Fan card: titles/labels from `FanDescriptor.label`; temp shown from the descriptor's `temp_source`; drop "left fan (CPU)" physical assumptions (main.rs:949-956, 1592).
- **UI gap — curve create/delete**: add New Curve (name input, starts from copy of defaults/current) and Delete Curve (refuses while any fan references it, offers reassign-to-auto) in the curve panel; wired to existing PutCurve/DeleteCurve IPC which already bump config_gen.

## 6. CLI

- `thermite fan cpu set 50` / `fan gpu ...` subcommands → `thermite fan <name> <action>` with dynamic name, plus `thermite fan list`. Doctor output reworded driver-agnostically (main.rs:170-173).

## 7. Verification & deploy
